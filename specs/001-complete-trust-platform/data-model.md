# Data Model: Complete Trust Platform

## Core Tenancy and Access

### Organization

- **Fields**: `id`, `name`, `status`, timestamps.
- **Relationships**: owns users, roles, leads, projects, risks, and health
  events.
- **Validation**: protected actions require active organization status.

### Pilot User

- **Fields**: `user_id`, `org_id`, `role`, `status`.
- **Relationships**: links auth users to organizations for legacy and runtime
  checks.
- **Validation**: inactive, pending, or suspended users fail closed.

### Role Assignment

- **Fields**: `organization_id`, `user_id`, `role_id`,
  `permission_template_id`, `status`.
- **Relationships**: maps users to current role and permission template.
- **Validation**: only active role assignments grant permissions.

### Permission Template

- **Fields**: `organization_id`, `name`, `status`.
- **Relationships**: contains permission ids through template permissions.
- **Validation**: archived templates cannot grant new protected access.

## Broker and Caller Profiles

### Broker Public Profile

- **Fields**: `id`, `linked_user_id`, `organization_id`,
  `assigned_sourcing_manager_id`, `broker_alias`, `broker_name`,
  `company_name`, `area`, `city`, `status`, trust/performance metadata.
- **Relationships**: source for lead attribution and broker locks.
- **Validation**: `source_broker_id` points here; `broker_id` on leads remains
  auth user id where expected by legacy schema.

### Broker Sensitive Profile

- **Fields**: `broker_id`, encrypted contact fields, encryption metadata.
- **Relationships**: one-to-one with broker public profile.
- **Validation**: no authenticated frontend reads.

### Sourcing Manager Public Profile

- **Fields**: `linked_user_id`, `organization_id`, `manager_name`, `city`,
  `status`.
- **Relationships**: assigned to brokers, leads, visits, and proposals.
- **Validation**: safe metadata only.

### Caller Profile

- **Fields**: `linked_user_id`, `organization_id`, `caller_name`, `city`,
  `status`.
- **Relationships**: receives data loans and call assignments.
- **Validation**: safe metadata only; active status required for call work.

## Lead and Call Flow

### Lead Public

- **Fields**: `id`, `broker_id`, `source_broker_id`, `organization_id`,
  `lead_alias`, `area`, `budget_range`, `project_interest`, `lead_status`,
  `conversion_stage`, `brokerage_status`, assignment fields.
- **Relationships**: parent of sensitive data, data loans, call attempts, site
  visits, broker locks, audit events.
- **Validation**: metadata only; no restricted contact fields.

### Lead Sensitive

- **Fields**: `lead_id`, encrypted contact payload, hash, encryption metadata.
- **Relationships**: one-to-one with lead public.
- **Validation**: service-role only; no direct authenticated read.

### Data Loan

- **Fields**: `lead_id`, `granted_to_user_id`, `purpose`, `status`,
  `expires_at`.
- **Relationships**: permits caller or actor to use protected call action.
- **State**: `active` -> `expired` or `revoked`.

### Call Attempt

- **Fields**: `lead_id`, `caller_id`, `data_loan_id`, `provider`, `status`,
  provider reference, callback metadata.
- **Relationships**: generated by secure call initiation and provider callback.
- **Validation**: forged callbacks cannot transition successful state.

### Broker Follow-up

- **Fields**: `broker_id`, `project_id`, `assigned_to`, `due_at`, `priority`,
  `status`, safe reason.
- **Relationships**: queued by caller or broker workflow tools.
- **Validation**: safe notes only.

## Site Visit and Lock Flow

### Site Visit Proposal

- **Fields**: `source_broker_id`, `source_lead_id`, `project_id`,
  `assigned_sourcing_manager_id`, `status`, schedule metadata, safe notes.
- **Relationships**: creates scheduled site visits.
- **State**: `proposed` -> `accepted/scheduled` or `rejected/cancelled`.

### Site Visit

- **Fields**: `lead_id`, `source_lead_id`, `source_broker_id`, `broker_id`,
  `project_id`, `sourcing_manager_id`, `status`, GPS/photo/proof fields.
- **Relationships**: proof confirmations, site visit proofs, broker locks.
- **State**: scheduled -> started -> gps_verified -> photo_uploaded ->
  visit_done/completed, with invalid/no_show/rejected fail-closed exits.

### Site Visit Proof

- **Fields**: `site_visit_id`, `confirmation_id`, `proof_type`, `status`,
  GPS metrics, proof hash/path, `verified_by`.
- **Relationships**: mirrored from site visit confirmations.
- **Validation**: metadata only; no contact tokens in proof paths.

### Broker Lock

- **Fields**: `lead_id`, `broker_id`, `source_site_visit_id`, `status`,
  `starts_at`, `expires_at`, `brokerage_status`, proof metadata.
- **Relationships**: created or extended after proof-backed visit completion.
- **State**: active -> expired/revoked/disputed.

## Developer, Governance, and Evidence

### Project and Inventory Unit

- **Fields**: project metadata, geofence coordinates/radius, unit availability.
- **Relationships**: visits and developer lead bank.

### Developer Lead Bank

- **Fields**: `organization_id`, `project_id`, `lead_id`, `source_broker_id`,
  `assigned_sourcing_manager_id`, `lead_alias`, lifecycle and attribution
  status, metadata.
- **Relationships**: safe developer-side view of lead pipeline.

### Audit Event

- **Fields**: `actor_id`, `organization_id`, `lead_id`, `event_type`,
  `event_context`, `created_at`.
- **Validation**: append-only and PII-safe.

### Abuse Event, Risk Notification, Trust Score, System Health Event

- **Fields**: safe event type, status, severity, target metadata, timestamps.
- **Relationships**: super-admin governance and risk dashboards.

## Deterministic Lead State Transitions

```text
intake -> assigned -> data_loan_active -> call_queued -> call_completed
call_completed -> visit_proposed -> visit_scheduled -> visit_started
visit_started -> gps_verified -> photo_submitted -> visit_verified -> locked
any protected step -> invalid/lost only through explicit fail-closed transition
```
